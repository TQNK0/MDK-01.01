КОНСПЕКТ ПО ЖЦ ПО

Жизненный цикл разработки ПО (SDLC)
ЖЦ — путь, который проходит продукт: от момента задумки до вывода из эксплуатации.

Этапы ЖЦ ПО
1. Планирование и анализ требований
*Описание задач, которые должен решать продукт
*Опрос стейкхолдеров
*Выявление аудитории
*Оценка ресурсов (сотрудники, время, бюджет)
*Согласование критериев успешности

2. Определение требований
*Оценка рисков
*Выбор методологии разработки
*Описание пользовательских сценариев
*Подготовка SRS и ИСР

3. Проектирование
Верхнеуровневое	            Низкоуровневое
Основные компоненты системы	Принцип работы отдельных компонентов
Взаимодействие компонентов	Алгоритмы и логика внутри модулей
Общая архитектура	           Детали реализации (классы, методы)
Зависимость от других систем	Взаимодействие с БД и API

4. Разработка
*Написание кода, интеграция компонентов
*Модульное тестирование

5. Тестирование
*Интеграционное, системное, пользовательское
*Ошибки отправляются разработчикам

6. Развертывание
*Выпуск в боевую среду
*Подготовка документации

7. Поддержка и сопровождение
*Обновление ПО, исправление ошибок
*Техподдержка пользователей

8. Смерть ПО
*Прекращение обслуживания или замена
*Архивирование данных

Модели жизненного цикла разработки ПО
*Каскадная (Waterfall)
Последовательное выполнение этапов
Переход только вперёд, возврат затруднён
Полное документирование до старта

*V-образная
Упор на тестирование
Каждому этапу — этап проверки
Верификация и валидация

*Итеративная
Разработка итерациями
В каждой итерации — все этапы
Постепенное наращивание функциональности

*Инкрементная
Продукт по частям (инкрементам)
Каждая часть — новая функциональность
Возможность выпуска частями

*Спиральная

Сочетание итеративности и анализа рисков
Каждый виток — новая версия
Постоянная оценка рисков

*Agile
Гибкая разработка
Короткие итерации (спринты)
Постоянное взаимодействие с заказчиком
Быстрая реакция на изменения

*Scrum (фреймворк Agile)
Спринты 2–4 недели
В конце каждого — рабочий продукт
Ретроспектива

*Kanban (метод управления потоком)
Визуализация задач на досках
WIP-лимиты
Не замена модели, а улучшение процесса

Как выбрать модель
*Можно сочетать несколько подходов
*Agile Suitability Filter — опросник для выбора: предиктивный, гибкий или гибридный подход

Управление этапами (инструменты)
Kaiten — таск-трекер для любой модели:
*Канбан-доски для визуализации
*Шаблонные чек-листы
*Декомпозиция задач
*Спринты по Scrum
*Хранение документации
*Отчёты: Диаграмма Ганта, Накопительная диаграмма потока

Вывод: SDLC — база для организации разработки. Модели можно комбинировать. Главное — чтобы процесс приносил ценность заказчику и был удобен команде.

ПРАКТИЧЕСКАЯ

Markdown — язык разметки, который превращается в HTML. Используется в README-файлах, документации, на GitHub. Файлы с расширением .md.

Параграфы
Текст делится на параграфы пустыми строками. Если строки идут подряд без пропуска — они склеятся в одну. Чтобы перенести строку, есть три способа: два пробела в конце, обратная косая черта \ или тег <br>.

Привет,
мир!

Привет,  
пробел!

Привет,\
косая черта!

Привет,<br>
тег бр-р-р!

Заголовки
Заголовки бывают двух видов.
С решётками — ставим # перед текстом. Количество решёток — уровень заголовка (от 1 до 6).
# Заголовок 1 уровня
## Заголовок 2 уровня
### Заголовок 3 уровня
#### Заголовок 4 уровня
##### Заголовок 5 уровня
###### Заголовок 6 уровня

С подчёркиваниями — под текстом ставим === для первого уровня и --- для второго. Количество символов не важно. Между текстом и чертой не должно быть пустых строк.

Заголовок 1 уровня
==================

Заголовок 2 уровня
------------------

Заголовок, который подчеркнули одним символом
-

Заголовок второго
уровня из нескольких
строчек текста
------------------

Списки
Маркированные — перед пунктом ставим -, + или *.
- Помидор
- Огурец

+ Бублик
+ Ватрушка

* Молоко
* Кефир

Если использовать разные маркеры в соседних пунктах — получится несколько отдельных списков.
- Помидор
+ Бублик
* Молоко

Упорядоченные — ставим цифру с точкой. Можно везде ставить 1. — Markdown сам пронумерует по порядку. Если начать с 99. — нумерация пойдёт с 99.

1. Хлеб
2. Молоко
3. Помидоры

1. Хлеб
1. Молоко
1. Помидоры

99. Хлеб
1. Молоко
2. Помидоры

Вложенные списки — делаем отступ табом или пробелами. Количество пробелов зависит от длины маркера родительского пункта (L): + — 1 символ, 1. — 2 символа, 99. — 3 символа. Перед вложенным списком нужно от L + 1 до L + 4 пробелов.

+ Хлеб
+ Молочные продукты
  1. Кефир
  2. Ряженка

1. Молоко
2. Хлебобулочные изделия
    + Бублик
    + Ватрушка

Цитаты
Цитата начинается с > в начале строки. Внутри можно делать заголовки, списки, другие цитаты.
> Одна треугольная скобка
превращает в цитату несколько строк,
идущих друг за другом.

> # Цитаты великих людей
> Ваша работа заполнит большую часть жизни и единственный способ быть
> полностью довольным — делать то, что по-вашему является великим делом.
> И единственный способ делать великие дела — любить то, что вы делаете.
>
> *— Стив Джобс, Речь в Стенфорде*

> Первая, родительская цитата
> > А это уже вторая,\
> > дочерняя цитата

Код
Строчный код — обёртываем в бэктики. Даже если переносить строки — всё склеится в одну.
Функция `alert()`
вызывает диалоговое окно.

Сумму двух переменных
можно вывести так:
``const a = 1;
const b = 2;
alert(a + b);``

Блочный код — три бэктика. Если указать язык — будет подсветка синтаксиса.
Функция ```console.log()```
выводит текст в консоль.

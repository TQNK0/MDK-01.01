# КОНСПЕКТ ПО ЖЦ ПО

## Жизненный цикл разработки ПО (SDLC)

**ЖЦ** — путь, который проходит продукт: от момента задумки до вывода из эксплуатации.

---

## Этапы ЖЦ ПО

### 1. Планирование и анализ требований

- Описание задач, которые должен решать продукт
- Опрос стейкхолдеров
- Выявление аудитории
- Оценка ресурсов (сотрудники, время, бюджет)
- Согласование критериев успешности

### 2. Определение требований

- Оценка рисков
- Выбор методологии разработки
- Описание пользовательских сценариев
- Подготовка SRS и ИСР

### 3. Проектирование

#### Верхнеуровневое проектирование

- Основные компоненты системы
- Взаимодействие компонентов
- Общая архитектура
- Зависимость от других систем

#### Низкоуровневое проектирование

- Принцип работы отдельных компонентов
- Алгоритмы и логика внутри модулей
- Детали реализации (классы, методы)
- Взаимодействие с БД и API

### 4. Разработка

- Написание кода, интеграция компонентов
- Модульное тестирование

### 5. Тестирование

- Интеграционное, системное, пользовательское
- Ошибки отправляются разработчикам

### 6. Развертывание

- Выпуск в боевую среду
- Подготовка документации

### 7. Поддержка и сопровождение

- Обновление ПО, исправление ошибок
- Техподдержка пользователей

### 8. Смерть ПО

- Прекращение обслуживания или замена
- Архивирование данных

---

## Модели жизненного цикла разработки ПО

### Каскадная (Waterfall)

- Последовательное выполнение этапов
- Переход только вперёд, возврат затруднён
- Полное документирование до старта

### V-образная

- Упор на тестирование
- Каждому этапу — этап проверки
- Верификация и валидация

### Итеративная

- Разработка итерациями
- В каждой итерации — все этапы
- Постепенное наращивание функциональности

### Инкрементная

- Продукт по частям (инкрементам)
- Каждая часть — новая функциональность
- Возможность выпуска частями

### Спиральная

- Сочетание итеративности и анализа рисков
- Каждый виток — новая версия
- Постоянная оценка рисков

### Agile

- Гибкая разработка
- Короткие итерации (спринты)
- Постоянное взаимодействие с заказчиком
- Быстрая реакция на изменения

### Scrum (фреймворк Agile)

- Спринты 2–4 недели
- В конце каждого — рабочий продукт
- Ретроспектива

### Kanban (метод управления потоком)

- Визуализация задач на досках
- WIP-лимиты
- Не замена модели, а улучшение процесса

---

## Как выбрать модель

- Можно сочетать несколько подходов
- **Agile Suitability Filter** — опросник для выбора: предиктивный, гибкий или гибридный подход

---

## Управление этапами (инструменты)

**Kaiten** — таск-трекер для любой модели:

- Канбан-доски для визуализации
- Шаблонные чек-листы
- Декомпозиция задач
- Спринты по Scrum
- Хранение документации
- Отчёты: Диаграмма Ганта, Накопительная диаграмма потока

---

## Вывод

**SDLC** — база для организации разработки. Модели можно комбинировать. Главное — чтобы процесс приносил ценность заказчику и был удобен команде.
